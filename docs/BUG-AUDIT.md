# v8.1 Production Bug Audit

Status vocabulary:
- **IMPLEMENTED**: source fix and regression coverage are present in this tree.
- **WINDOWS-VERIFY**: must still be compiled/executed with the .NET 10 Windows toolchain before release use.

This audit deliberately separates implementation from runtime proof. The current build workspace does not contain the .NET SDK or Windows/WPF runtime, so no issue is labeled runtime-verified here.

## Root-cause discipline

A symptom is not considered repaired by adding sleeps, increasing timeouts, swallowing exceptions, forcing GC, disabling integrity checks, or deleting State. The intended proof chain is:

`reproduction -> structured evidence -> root cause -> source fix -> regression fixture -> fault/stress verification`.

## Runtime verification still required

Run `scripts/release/Verify-Release.ps1` on Windows with the .NET 10.0.401-or-newer SDK. Runtime proof must include clean build/analyzers, unit tests, integration/fault-injection tests, database integrity check, benchmark collection, and a WPF responsiveness/soak pass. See `VALIDATION.md` and `docs/DIAGNOSTICS.md`.
