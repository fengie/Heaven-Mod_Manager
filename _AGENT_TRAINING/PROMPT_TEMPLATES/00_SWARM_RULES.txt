# SWARM RULES — SHARED DELTA

This file contains only multi-agent rules. All agents already inherit AGENTS.md and _AGENT_TRAINING/AGENT_OPERATING_STANDARD.md; do not repeat those contracts here.

## WHEN TO PARALLELIZE

Delegate when work can be split into independent, bounded outputs whose synthesis cost is lower than doing the work inline. Good lanes include separate investigations, distinct components, independent review, focused tests, and mechanical evidence gathering.

Keep short tasks, tightly ordered dependency chains, single mutable state transitions, and same-file editing with one owner.

## OWNERSHIP

- One primary owner per mutable boundary.
- Check live branches/PRs/leases before assigning overlapping work.
- A reviewer/tester may inspect the same boundary without becoming a competing implementation owner.
- A replacement inherits the exact durable checkpoint; it does not restart completed work.
- Agent disappearance or stale prose is not completion evidence.

## ASSIGNMENT CONTRACT

Each worker gets only what it needs:

- objective and acceptance criterion;
- mutable boundary and likely source/tests;
- relevant repository/context references;
- dependencies and non-goals;
- expected artifact/evidence;
- required verification;
- branch/integration expectations when mutation is authorized.

Do not paste the full repository history or shared operating contract into every assignment.

## RETURN CONTRACT

A worker returns concise, verifiable state: status, exact revision/branch, artifact or finding, checks/results, unresolved risk/blocker, and next action. Research-only workers distinguish facts from hypotheses. Implementers return working changes, not just recommendations, unless explicitly assigned review/research.

The owning/manager agent must inspect and synthesize returned work. Subagent confidence is not integration evidence.

## RECOVERY

Use bounded retries. Preserve useful partial artifacts before replacement. If an unchanged external blocker survives the current iteration, mark a durable deferred state and move future scheduled cycles to different actionable work until evidence shows the blocker changed.

## CONVERGENCE

Parallelism ends in one coherent canonical result. Reconcile dependencies, preserve unique work, run affected exact-candidate checks, verify the canonical tree, and retire temporary branches/leases only after their useful content and evidence are accounted for.
